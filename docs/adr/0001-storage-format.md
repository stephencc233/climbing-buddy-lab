# ADR 0001：记录数据的存储格式

- 状态：已采纳
- 日期：2026-10-09

## 背景
需求 AC1.5 要求记录在程序重启后仍然存在，因此必须选定一种持久化格式。影响选择的约束有：

- 线路类型是多选字段，每条记录含一个列表；
- lab 是练习原型，数据量很小（4 周验证期约数百条），重点是实现简单、便于查看和排错；
- 统计计算在核心层用 Python 完成，存储层只负责保存和读取；
- 仓库是公开的，个人训练数据不能进入版本库。

## 可选方案
1. JSON 文件：整个记录列表存为一个 JSON 文件
2. CSV 文件：每条记录一行
3. SQLite：使用标准库 sqlite3

## 决定
采用 JSON 文件，存储位置在仓库之外（或已加入 .gitignore 的数据目录）。

## 理由
1. 多选类型天然用列表表达；CSV 需要自定义单元格内分隔符，SQLite 需要额外的表或 JSON 列。
2. 文件可以直接打开查看和手工修正，适合原型阶段排错，也便于核对统计结果。
3. 标准库自带，不增加依赖，实现成本最低；SQLite 的事务和查询能力在当前数据量下用不上。

## 后果
- 好处：存储层代码最少；数据结构可以自然扩展到正式版的“训练 → 线路 → 尝试”层级。
- 代价：每次保存都要重写整个文件，写到一半时崩溃可能损坏数据。
  - 应对：先写入临时文件，再用 os.replace 替换原文件（Windows 上的原子性在 U04 实现时查官方文档核实）。
- 代价：将来如果更换格式，需要写迁移脚本。
  - 应对：文件顶层带一个 schema_version 字段；存储层与核心层分离，换格式只影响存储层。
- 约束：数据文件不提交到仓库，在 .gitignore 中排除。
- 复审时机：正式版 P3 设计时重新评估；如果记录量或并发写入需求明显增长，再考虑 SQLite。
