# ADR 0003：完攀率在“无记录”时由核心层返回 None

- 状态：已采纳
- 日期：2026-10-12
- 执笔：Claude 起草，Stephen 审阅（方案由 Stephen 委托 Claude 评估决定）

## 背景
需求第 4 节和 AC3.2 要求：筛选结果为空时显示“本周未进行该<难度/类型/角度>攀爬”，不显示 0%，也不报错。而 `core.send_rate(sent_routes, logged_routes)` 在 `logged_routes == 0` 时抛 `ZeroDivisionError`（M4 预留的 bug，U06 已定位到 `core.py:10`）。

修复前必须先定下：“空结果”由哪一层识别，用什么方式告诉调用方。影响选择的约束：

- 架构分三层，入口层形态未定、**可整体替换**（命令行 / 网页），核心层是纯逻辑、不做 I/O（`CLAUDE.md`、ADR 0001）。
- “有记录但一条都没完攀”（0%）和“没有记录”是两种不同的结果，前者应显示 0.0%，后者不能。
- U06 的 AI 实践还发现了需求没写到的输入：`(1, 0)`、`sent > logged`（会静默返回超过 100% 的值）、负数。

## 可选方案
1. 核心层返回 `None`（返回类型 `float | None`），入口层遇到 `None` 显示提示文字
2. 核心层抛专门的异常（如 `NoRoutesLoggedError`），入口层捕获后显示提示文字
3. 入口层先判断 `logged_routes == 0`，核心层把 0 当作非法输入
4. 核心层返回结果对象（dataclass，含条数、比例、是否为空）

## 决定
采用方案 1：

- `logged_routes == 0` 且 `sent_routes == 0` → 返回 `None`，表示“无数据”。
- 不可能来自正确数据的输入 → 抛 `ValueError`：任一参数为负数，或 `sent_routes > logged_routes`（包括 `(1, 0)`）。
- 提示文字（需要拼出难度 / 类型 / 角度）由入口层根据 `None` 生成；百分比格式化仍由入口层负责。

## 理由
1. **“空”是正常的业务状态，不是错误**：AC3.2 明确要求“不报错”，用返回值表达比用异常更直接（排除方案 2）。
2. **业务规则放在不可替换的一层**：“空结果不显示为 0%”是统计口径，放在核心层后所有入口层共享；方案 3 把它放进可替换的入口层，换形态时容易漏掉，结果就是显示 0% 或崩溃。
3. **把“空”和“错”分开**：负数和 `sent > logged` 说明上游数据或调用写错了，立即抛 `ValueError` 才能尽早暴露问题；如果也返回 `None`，会把程序错误伪装成“本周没练”。
4. **返回类型本身就是提醒**：签名写成 `float | None`，调用方读签名就知道要处理 `None`；U08 开启 Pylance 类型检查后还能由工具检查。
5. 方案 4 更利于扩展，但现在只有一个函数，属于过度设计；P3 设计“按周统计”接口时再考虑。

## 后果
- 好处：
  - AC3.2 的“不报错、不显示 0%”在核心层就有测试保证（`tests/test_core.py`）。
  - 0% 与“无数据”在类型上可区分：`0.0` 与 `None`。
- 代价 / 风险及应对：
  - 每个调用方都必须处理 `None`。如果直接写 `f"{rate:.1%}"`，遇到 `None` 会抛 `TypeError`。
    - 应对：入口层的格式化集中在一个函数里；U08 用类型检查兜底。
  - 输入校验让函数从 1 行变成多行，调用方需要知道会抛 `ValueError`：在 docstring 中写明。
- 约束：
  - 核心层所有“比例”类统计沿用同一约定：分母为 0 返回 `None`，非法计数抛 `ValueError`。
  - 核心层不返回任何展示用文字。
- 复审时机：P3 设计正式版 `climbing-buddy` 的统计接口时（考虑方案 4）。

## 核实记录

### 2026-10-12（U08）：理由 4“由类型检查提醒调用方处理 None”的实测

- 实测前：仓库没有配置类型检查模式，Pylance 默认 `off`，编辑器**不会**提示漏判 `None`，理由 4 当时并不成立。
- 已在 `pyproject.toml` 加 `[tool.pyright]`（`typeCheckingMode = "standard"`），Pylance 与命令行 pyright（dev 组，提交前钩子与任务都会运行）共用这一配置。
- 能查出的漏判（pyright 1.1.414，basic 与 standard 结果相同）：算术、比较、`round()`、传给 `float` 参数、作为 `-> float` 的返回值、调用 `float` 的方法。
- **查不出**：`f"{rate:.1%}"` 和 `format(rate, ".1%")`。`None` 继承的 `object.__format__` 接受任意格式字符串，类型层面看不出问题，运行时才抛 `TypeError: unsupported format string passed to NoneType.__format__`（mypy 2.4.0 只能查出 `"{:.1%}".format(rate)` 这种字面量写法，ty 0.0.86 也查不出）。
- 结论：理由 4 部分成立。格式化这一类由 `format_send_rate` 的测试和“格式化集中在入口层一个函数里”的约定兜底，后果一节的应对措施保持不变。
